# HP_Crafter — крафтовый стол для DayZ

HP_Crafter добавляет в DayZ устанавливаемый крафтовый стол с отдельным интерфейсом рецептов. Рецепты, категории, требования к инструментам и настройки оформления загружаются сервером из JSON-файла профиля.

## Возможности

- Размещение стола из набора `HP_Crafter_Kit`.
- Открытие отдельного меню крафта действием **Start** у стола.
- Категории рецептов и карточки предметов с предпросмотром результата.
- Проверка наличия ингредиентов в грузовом отсеке стола и требуемых предметов в его слотах attachments.
- Поддержка предметов с количеством и обычных предметов.
- Для компонентов рецепта можно указать расходование, изменение состояния или сохранение предмета.
- Настраиваемые изображения фона и категорий меню.
- Разборка установленного стола обратно в набор через ванильный рецепт с отвёрткой.

## Установка

1. Установите папку мода `HP_Crafter` в каталог модов сервера и клиента.
2. Подключите мод в параметрах запуска сервера и клиента.
3. Запустите сервер один раз — мод создаёт/читает конфигурацию из профиля сервера.
4. Настройте JSON-файл рецептов и перезапустите сервер после его изменения.

Скрипты мода подключаются через `config.cpp` в модули Game, World и Mission. Для корректной работы мод должен быть установлен и на клиенте, и на сервере.

## Конфигурация рецептов

Файл конфигурации читается по пути:

```
$profile:HP/HP_Crafter.json
```

Это JSON-объект `CraftServerManager`, внутри которого находится `m_CraftClasses`. Основные данные:

- `CraftCategories` — массив категорий.
- `CraftCategory.CategoryName` — отображаемое название категории.
- `CraftCategory.CraftItems` — рецепты, входящие в категорию.
- `CraftItem` — описание одного рецепта.
- `CraftComponent` — один из ингредиентов рецепта.
- `CustomizationSetting` — пути к изображениям интерфейса.

### Структура рецепта

| Поле | Назначение |
|---|---|
| `Result` | classname создаваемого предмета |
| `ResultCount` | количество результата |
| `RecipeName` | название рецепта в меню |
| `CraftType` | тип/ключ изображения категории (например, `craftpic`, `weaponpic`, `repairpic`) |
| `CraftComponents` | массив требований к ингредиентам |
| `AttachmentsNeed` | массив classnames обязательных attachments на столе |
| `ComponentsDontAffectHealth` | параметр обработки состояния результата (в текущем коде усреднение состояния вычисляется, но присвоение результата закомментировано) |

### Структура компонента

| Поле | Назначение |
|---|---|
| `Classname` | classname ингредиента |
| `Amount` | требуемое количество; для предметов без quantity — число предметов |
| `Destroy` | `true` — расходовать компонент, `false` — сохранить/изменить его |
| `Changehealth` | изменение здоровья компонента при `Destroy = false` |

Пример фрагмента конфигурации (значения classnames и названия замените на свои):

```json
{
  "m_CraftClasses": {
    "CraftCategories": [
      {
        "CategoryName": "Инструменты",
        "CraftItems": [
          {
            "Result": "ПредметРезультат",
            "ResultCount": 1,
            "ComponentsDontAffectHealth": 1,
            "CraftType": "craftpic",
            "RecipeName": "Название рецепта",
            "CraftComponents": [
              {
                "Classname": "Ингредиент",
                "Amount": 2,
                "Destroy": true,
                "Changehealth": 0.0
              }
            ],
            "AttachmentsNeed": ["HP_Anvil"]
          }
        ]
      }
    ]
  }
}
```

> В примере показана вложенность данных `CraftClasses`. При подготовке полного файла сохраняйте остальные поля класса и корректный JSON-синтаксис. В репозитории отдельный готовый образец `HP_Crafter.json` не включён.

### Изображения интерфейса

`CraftType` сопоставляется с ключами изображений категорий. Встроенные варианты: `repairpic`, `paintpic`, `ammopic`, `weaponpic`, `toolspic`, `craftpic`, `sewingkitpic`, `buildingpic`, `carpic`, `furniturepic`, `medicpic`, `bookpic`, `housepic`, `donatepic`, `voltagepic`.

Пути к пользовательским изображениям задаются в `CustomizationSetting` (например, `PathToMainBackgroundImg`, `PathTocraftpicImg`, `PathToweaponpicImg`). Если пользовательское изображение не загрузилось, интерфейс использует встроенное.

## Использование в игре

1. Получите `HP_Crafter_Kit` и разместите его как обычный deployable.
2. Подойдите к установленному столу и выберите действие **Start**.
3. Выберите категорию, затем рецепт. В панели рецепта отображаются результат, требуемые ингредиенты и необходимые attachments.
4. Положите ингредиенты в cargo стола и установите требуемые инструменты/предметы в attachments.
5. Когда требования выполнены, кнопка крафта становится доступной. После запуска отображается прогресс, затем результат создаётся рядом с игроком.
6. Для разборки стола используйте ванильный рецепт: **отвёртка + HP_Crafter → HP_Crafter_Kit**.

## Как устроена система

- **CraftServerManager** загружает `$profile:HP/HP_Crafter.json` и хранит `CraftClasses`.
- **MissionServer** отправляет данные конфигурации подключившемуся игроку через RPC.
- **PlayerBase** получает конфигурацию, проверяет наличие ингредиентов на серверной стороне, обрабатывает расход/изменение компонентов и создаёт результат.
- **CraftManager** на клиенте хранит выбранный стол, открывает/закрывает меню и управляет временными объектами предпросмотра.
- **CraftHud** формирует категории и рецепты, отображает ингредиенты, проверяет локально cargo и attachments, запускает визуальный прогресс и отправляет RPC на сервер.
- **ActionInteractWithTable** открывает интерфейс по действию Start.
- **HP_Crafter_Kit / Hologram** реализуют установку стола; **DECRAFT_Table** добавляет ванильный рецепт разборки.

## Важные особенности текущей реализации

- Ингредиенты берутся из **cargo установленного стола**, а не из инвентаря игрока.
- Обязательные attachments проверяются по classname и количеству совпадений.
- Для ингредиентов без quantity `Amount` означает количество экземпляров. Для предметов с quantity — требуемое количество единиц.
- Результат создаётся на земле в позиции игрока, а не автоматически помещается в его инвентарь.
- Клиентская проверка нужна для интерфейса; окончательная проверка наличия ингредиентов выполняется сервером.
- Состояние здоровья компонентов учитывается в вычислениях, однако перенос среднего здоровья на результат в текущем скрипте отключён комментарием.
- `HPCClassnames` присутствует в структуре данных, но в текущих скриптах крафта не используется.

## Состав проекта

- `config.cpp` — регистрация модулей, предметов, стола, набора и attachments.
- `scripts/3_Game/Enums/HPCc.c` — идентификаторы RPC.
- `scripts/4_World/CraftManager/` — структуры рецептов, менеджеры и UI.
- `scripts/4_World/Classes/Actions/` — действие взаимодействия со столом.
- `scripts/4_World/Classes/recipes/DECRAFT_Table.c` — рецепт разборки.
- `scripts/4_World/Entities/` — классы стола, набора, hologram и PlayerBase.
- `scripts/5_Mission/mission/` — инициализация, обработка подключения и клиентского меню.
- `scripts/4_World/layout/` и `data/` — интерфейс, изображения, модели и текстуры.
- `languagecore/stringtable.csv` — локализация.
